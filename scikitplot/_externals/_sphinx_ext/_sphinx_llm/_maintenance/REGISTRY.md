## Cross-submodule boundaries

- `_sphinx_llm` is reviewed first because it is the producer.
- Runtime assistant/browser consumption is static-artifact based.
- A future Python facade, if retained, is build-time only and must be public/stable.
- Corpus may later ingest artifacts, but retrieval/chunking/indexing remains
  Corpus-owned.
- MCP may expose/use artifacts, but protocol/wire behavior remains MCP-owned.
- Backend/service security findings do not migrate into `_sphinx_llm` merely
  because the assistant consumes generated documentation.
