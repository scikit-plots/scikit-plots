# Run 15 — CY-007 (guide Part II §30) — sparse IDs vs dense sequence contract

**Priority:** P1  **Area:** `annoy/_annoy/annoylib.pyx.in` (`__len__`/`__contains__`/`__iter__`)  **Gate tier:** ring

## Finding (contract mismatch)
annoy's ID domain is sparse (`add_item` may leave gaps). The Index exposed
Python sequence protocols whose **docstrings promised dense-occupancy semantics**
("number of items", "True if item exists", "all vectors") while the **code was
extent-based**: `len` = `get_n_items_w()` (max id + 1), `x in idx` = `x < len`,
`iter` = `self[i]` over `[0, len)`. So on a sparse index (`add_item(0)`,
`add_item(5)`): `len == 6` (only 2 present), `1 in idx` is a gap false-positive,
and iteration yields 4 placeholder vectors.

## Model decision (guide requires choosing one public model)
- **Model A** (reject non-contiguous IDs) contradicts annoy's sparse design and
  `holes_test` — rejected.
- **Model B** (true occupancy: `len`=count, membership=occupancy) requires an
  occupancy structure that **cannot be reconstructed after a native `load`**
  (the serialized blob doesn't store it; a gap and a genuinely-zero item are
  indistinguishable). It needs a format/state change — deferred to the §6.6 /
  CY-018 format-contract decision.
- **Model C adopted:** the core is a low-level sparse/extent array. The three
  protocols are already mutually consistent under the extent model
  (`len` == #iterations == valid-`in` range == valid `__getitem__` range, per
  R12). Fix is to make the **documented contract match** that behavior and lock
  it, rather than fake occupancy the core can't persist. Zero new state,
  non-breaking, R12-consistent.

## Fix
Rewrote the `__len__` / `__contains__` / `__iter__` docstrings to state the
extent/array contract precisely: `len` is the ID extent (not a count);
`in` is ID-range validity in `[0, len)` (gap IDs are in-range and return the
native zero vector — NOT an occupancy claim); iteration walks the extent
consistent with `__getitem__`. Behavior unchanged (it was already correct under
this model). Diff: `out/annoylib.pyx.in.run15.diff`.

## Verification
`tests/test_sparse_sequence_contract.py` (5) locks the self-consistent extent
contract on a sparse index: `len` == extent (not count); `in` is exact
`[0, len)` range membership; `in` agrees with `__getitem__` accessibility over
the extent; iteration == extent-based `__getitem__` and yields the gap
placeholder (not skipped); empty index has extent 0. Ring green: annoy/_annoy
363, euclidean 12, holes 5, types 8, kiss 123.

## Observation (separate, not fixed here)
`__getitem__` applies Python negative-index wraparound (`idx[-1]` → last), while
`__contains__` treats negatives as strict out-of-range. That `__getitem__`-only
divergence is a minor Pythonic-convenience inconsistency distinct from the
sparse/dense contract; left as a small follow-up to avoid scope creep.
