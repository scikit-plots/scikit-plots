# Run 17 — CY-011 (guide Part II §35) — broken sklearn tags delegation

**Priority:** P1/P2  **Area:** `annoy/_annoy/annoylib.pyx.in` (`Index.__sklearn_tags__`)  **Gate tier:** ring

## Finding (runtime-verified)
`Index.__sklearn_tags__` was `return super().__sklearn_tags__()`. The MRO is
`Index -> BaseIndex -> _HTMLDocumentationLinkMixin -> ReprHTMLMixin -> object`
— no sklearn `BaseEstimator` — so the call raised
`AttributeError: 'super' object has no attribute '__sklearn_tags__'`. Any sklearn
machinery that reads tags (sklearn >= 1.6) would crash. `clone` worked (it uses
`get_params`/`__init__`).

## Fix (guide decision: version-safe tag provider)
The class is estimator-*like* (`get_params`/`set_params`/`clone`) but is a Cython
extension type, so inheriting `BaseEstimator` (a Python class) is impractical and
would make sklearn a hard dependency. Instead `__sklearn_tags__` now delegates to
sklearn's ROOT tag builder, which constructs default `Tags` from scratch (its body
is `return Tags(...)`, no `super()`):

```python
from sklearn.base import BaseEstimator
return BaseEstimator.__sklearn_tags__(self)
```

This is version-safe (whatever sklearn is installed builds its own correct
defaults for `self`), keeps sklearn optional (lazy import; sklearn < 1.6 never
calls `__sklearn_tags__`), and needs no fake inheritance. Diff:
`out/annoylib.pyx.in.run17.diff` (method body only, one file).

## Verification
`tests/test_sklearn_tags.py` (4, `importorskip('sklearn')`): `__sklearn_tags__()`
returns a `Tags` (no AttributeError); the public `sklearn.utils.get_tags(idx)`
accessor works; `clone` still round-trips params; and tags carry sensible defaults
(`estimator_type is None` for a neighbors-style index). Verified live against
sklearn 1.8.0; `get_tags(idx)` -> `Tags`. Ring green: annoy/_annoy 375,
euclidean 12, kiss 123.

## Note
Pre-1.6 sklearn uses the dict-based `_get_tags`/`_more_tags` protocol and never
calls `__sklearn_tags__`, so no pre-1.6 shim is needed. If full estimator
conformance is later desired, `check_estimator` compliance is a broader,
separate effort (fit/predict API surface), not part of this tag-delegation fix.
