# Decide how the detection view treats look-alike characters from other scripts

## Summary

Round 25's detection view (`_canonical.detection_view`) removes format
characters and folds single-character compatibility forms. It deliberately
does not fold *confusables* — letters from another script that look like
ASCII (Cyrillic `U+0430` for Latin `a`, Greek `U+039F` for `O`). A value
spelled with one is not detected.

## Why it matters

Homoglyph substitution is a known way to slip a value past a pattern while a
person — or a model — reads it unchanged.

## Current evidence

`encode("mail " + "\u0430" + "da@example.com").text` is unchanged on round 25
(it also interacts with the `EMAIL` boundary; see
`email-addresses-with-non-ascii-letters.md`).

## Root cause / current understanding

Unicode has no normalisation form for confusables; the Unicode security
mechanism (UTS #39 "skeleton") is a mapping table that the standard library
does not ship.

## Expected behavior

To be decided; options in order of preference:

1. Ship a small, versioned, generated table of the confusables that map to
   ASCII letters and digits (from UTS #39 `confusables.txt`), used only by the
   view (one character to one character keeps the offset map trivial).
2. Report, not fold: `inspect` flags mixed-script tokens adjacent to a
   structural near-match as a suggestion for `--hide`.

## Affected paths and ownership

`_canonical.py` (table, view), `tests/test__canonical.py`,
`tests/test__engine.py` (`TestDetectionView`).

## Constraints and non-goals

Never fold in the source text; the vault keeps the original. Do not fold
legitimate non-Latin text into ASCII outside the view. Base tier only (a
generated table committed to the package, regenerated by a tool, with the
Unicode version recorded).

## Edge cases to cover

Mixed-script words in genuine Cyrillic or Greek prose (no false positives
introduced by the view alone, since the view only adds spans that a pattern
validates); a confusable inside a key; restore exactness.

## Proposed direction

Option 1, after the `EMAIL` boundary fix.

## Verification / acceptance criteria

Salted-scale probe with confusables, as `V25` does with format characters.

## Documentation impact

`how_it_works.rst` (the detection view), `security_and_limits.rst`.

## Release-note promotion

Decide with the implementation.
