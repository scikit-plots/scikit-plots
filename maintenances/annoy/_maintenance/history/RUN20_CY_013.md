# Run 20 — CY-013 (guide Part II §39) — advisory dtype params were unchecked

**Priority:** P2  **Area:** `annoy/_annoy/annoylib.pyx.in` (`Index.__init__`)  **Gate tier:** ring

## Finding (runtime-verified)
`index_dtype` and `dtype` are validated at construction (invalid values raise),
but `wrapper_dtype` and `random_dtype` were assigned with no validation:
`A.Index(4,'euclidean', wrapper_dtype='xyz')` and `random_dtype='nope'` were
accepted silently and then reported back by `get_params()`. The code comment
already noted these are "informational, not used for dispatch" — so they were
both informational AND unchecked, producing meaningless metadata.

## Fix (parameter honesty)
Validate `wrapper_dtype`/`random_dtype` against their documented set
`{"uint32", "uint64"}` at construction (raising a clear `ValueError`, mirroring
`index_dtype`/`dtype`), while keeping them advisory. Updated the parameter
docstrings to state explicitly that they are "Advisory metadata only (not used
for concrete dispatch)" with the valid values. No dispatch/behaviour change.
Diff: `out/annoylib.pyx.in.run20.diff`.

## Verification
`tests/test_advisory_dtype_validation.py` (17): invalid advisory dtypes rejected
(`xyz`/`nope`/`float64`/`int32`/`""`); valid ones (`uint32`/`uint64`) accepted and
round-trip in `get_params()`; defaults unchanged; the advisory label does not
alter query results (same nns for `uint32` vs `uint64`); docstring marks them
advisory. Ring green: annoy/_annoy 392, euclidean 12, kiss 123.

## Build note (recorded for the recipe)
The heavy annoy extension compile exceeds a single sandbox command timeout. A
`.pyx.in` edit needs, in sequence: `touch annoylib.pyx.in` -> build the
`annoylib.pyx` target (tempita regen) -> build the `.so` target across two
resumes (Cython->cpp, then cpp->link). Copy the `.so` only after the final
`[..] Linking target` line; verifying a compiled docstring/behaviour is the way
to catch a stale `.so`.
