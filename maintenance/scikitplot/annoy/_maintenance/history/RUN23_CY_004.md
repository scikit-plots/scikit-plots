# Run 23 — CY-004 (guide Part II §28) — deallocation fault-model ambiguity

**Priority:** P1  **Area:** `cexternals/_annoy/src/annoylib.h` + `annoy/_annoy/annoylib.pyx.in`  **Gate tier:** ring + C++

## Finding
The guide asks: can `_destroy_index()` (called from `__dealloc__`) establish a
Python exception during deallocation? The dealloc path calls `self.ptr.unload()`
then `del self.ptr`. Two ambiguities:
1. `_destroy_index`'s own docstring claimed *"unload() is 'except +'"* and
   justified "must not be nogil" on that basis — but R7/R18 made `unload()`
   `noexcept`. The code documented a false fault model.
2. The concrete C++ destructors `~AnnoyIndex()` / `~HammingWrapper()` were only
   IMPLICITLY noexcept (base dtors are `noexcept = default`, `unload()` is
   `noexcept`), never explicitly declared — so the no-fail guarantee was not
   enforced.

## Fix (prove no-fail; correct the model)
- C++: declared the concrete destructors `noexcept` (`~AnnoyIndex() noexcept`,
  `~HammingWrapper() noexcept`). Their bodies only call the no-throw `unload()`,
  so this is compiler-enforced no-fail. Diff: `out/annoylib.h.run23.diff`.
- Cython: corrected the `_destroy_index` docstring to state the real no-fail path
  — `unload()` and the destructors are `noexcept`, so neither native call can
  raise during dealloc; the GIL is required only for the Python attribute
  accesses (not for exception conversion). Diff: `out/annoylib.pyx.in.run23.diff`.

## Verification
- **Compile-time proof** — `tests/test_dealloc_noexcept.cpp`:
  `static_assert(std::is_nothrow_destructible<AnnoyIndex<...>>)` for two concrete
  specializations + a `delete` through the `AnnoyIndexInterfaceBase*` ownership
  pointer. Fails to compile if a destructor regresses to throwing. Prints
  "0 failures".
- **Runtime fault model** — `tests/test_dealloc_fault_model.py` (6): del under
  partial init, built, double-unload, unload-before-build, mmap-backed (loaded),
  and 200 create/destroy cycles — none crash or raise.
- Ring green (both modules rebuilt): annoy/_annoy 428, cexternals fd_sentinel 1,
  kiss 123.
